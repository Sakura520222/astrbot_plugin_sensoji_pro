## 4. 经验教训

### 未来审查关注要点
- **键重构的影响面**：除了主数据字典，还要搜索所有使用该键作为索引的变量（如 `change_counts`、缓存、LRU）。
- **“锁 + I/O” 组合**：每次看到锁 + 文件读写，都要确认是否使用异步 I/O，以及锁内操作是否足够轻量。
- **“迁移 + 持久化” 的原子性**：迁移应在锁内完成，且持久化应只发生一次（在锁释放前）。

### 特定技术/模式审查经验
- **复合键迁移模式**：推荐在 `load_data` 阶段统一做一次原地迁移并立刻保存，而不是分散到各个业务方法中。
- **防御性 fallback 的隐患**：多处 fallback 会让代码路径复杂，且掩盖调用方错误。应使用 `assert` 或显式要求参数，删除 fallback。
